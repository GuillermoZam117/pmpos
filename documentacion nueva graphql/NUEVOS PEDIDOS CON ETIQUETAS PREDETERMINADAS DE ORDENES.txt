# Flujo Definitivo: **Pedido Nuevo + Etiquetas** (Tickets Abiertos / No Pagados)

> **Objetivo:** Crear un ticket nuevo, agregar productos y aplicar etiquetas de orden (Order Tags) mapeadas en SambaPOS, verificando y cerrando el ticket.
>
> **Convenciones:**
>
> * `terminalId` es el hash retornado por `registerTerminal` (no confundir con el **nombre** del terminal).
> * `ticketId` cuando se use se envía como **String**.
> * Nombres de grupos/tags deben coincidir **exactamente** como en SambaPOS.

---

## 1) Registrar terminal

**Payload**

```graphql
mutation {
  registerTerminal(
    ticketType: "COMEDOR"
    terminal: "SERVIDOR"
    department: "MESAS"
    user: "CAJERO"
  )
}
```

**Response**

```json
{
  "data": {
    "registerTerminal": "bZR5OnHI3kyPnrsqbehUrg"
  },
  "errors": null
}
```

## 3) Añadir pedido al ticket

**Payload**

```graphql
mutation {
  addOrderToTerminalTicket(
    terminalId: "bZR5OnHI3kyPnrsqbehUrg"
    productName: "CUARTO POLLO"
    portion: "Normal"
    quantity: 3
  ) { totalAmount }
}
```

**Response**

```json
{
  "data": { "addOrderToTerminalTicket": { "totalAmount": 195 } },
  "errors": null
}
```

## 7) Etiquetar pedido (por `orderUid`)

> Algunos builds no aplican `orderTags` en `addOrderToTerminalTicket`. La forma **robusta** es **actualizar la orden por `orderUid`**.

**Payload**

```graphql
mutation {
  updateOrderOfTerminalTicket(
    terminalId: "bZR5OnHI3kyPnrsqbehUrg"
    orderUid: "OwtuNGh_z0CStzb9lhnfrA"
    orderTags: [
      { tagName: "SABORES SALSAS POLLO", tag: "ADOBADO",     quantity: 1, price: 0 },
      { tagName: "PARA LLEVAR",          tag: "PARA LLEVAR", quantity: 1, price: 0 }
    ]
  ) {
    id
    totalAmount
    orders {
      uid name portion quantity price
      tags { tagName tag price quantity }
    }
  }
}
```

## Tips & Troubleshooting

* Si `orderTags` no surte efecto en `addOrderToTerminalTicket`, usa el **paso 7** (actualizar por `orderUid`).
* Para descubrir tags válidos **por orden** (respetando mapas/reglas), usa `getOrderTagsForTerminalTicketOrder(terminalId, orderUid)` si tu build lo expone.
* Nombres exactos (grupo y tag) y porción deben coincidir.
* `getOrderTagGroups(productId, terminal: <NOMBRE>)` usa **nombre de terminal**; mutaciones de Terminal usan **terminalId**.
* Si `getTerminalTicket` regresa `null`, el `terminalId` no tiene ticket activo o pertenece a otro usuario.
